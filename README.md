# AI 코딩 사고 플레이북

AI와 함께 앱을 만들면서 실제로 겪은 사고를 규칙으로 바꾸고, 그 규칙이 코드에서 무엇을 막았는지 기록한 모음입니다.
한 사람이 여러 프로젝트(Flutter 앱, FastAPI 서버, 로컬 도구)를 AI 협업으로 만들며 쌓은 패턴 문서와,
그 문서를 퀴즈가 붙은 강좌 페이지로 바꾸는 작은 빌드 도구로 되어 있습니다.

**사이트 바로 보기**: 저장소 오른쪽 소개란(About)의 웹사이트 링크
(같은 내용이 `docs/index.html` 한 파일에 들어 있어 오프라인으로도 열립니다)

사이트에서 볼 것:
- **규칙·퀴즈**: 사고에서 나온 패턴 문서와, 규칙마다 붙은 문제
- **프로젝트**: 17개 프로젝트 카드 — 무엇을 만들었고, 설계에서 무엇을 지켰고, 무엇으로 확인하는지
- **결정**: 11개 프로젝트의 설계 전환점 42건을 최신순으로. 결정마다 버린 대안, 어떻게 검증했는지, 앞선 결정을 뒤집었는지를 함께 남겼고, 확인하지 못한 것은 "아직 확인 못 함"으로 그대로 적었습니다

## 사고 → 규칙 → 코드 → 효과, 세 가지 예

### 1. 게이트가 실패했을 때 열 것인가 닫을 것인가

- **사고**: 하루 전송 한도를 확인하려고 저장소를 읽는데, 그 읽기가 실패하면 "0건"으로 보고 통과시키는 코드가 되기 쉽다. 사용자 대신 메시지를 보내는 앱에서는 한도를 모른 채 보내게 된다.
- **규칙**: 남용 방지용 한도는 장애 시 열고(fail-open), 결제·인증·되돌릴 수 없는 행동의 게이트는 닫는다(fail-closed). 기준은 "잘못 통과시킨 비용"과 "정상 요청을 잘못 막은 비용"의 비교.
- **코드**: 읽기 실패를 잡아 전송을 막고, 원인을 로그에 남기고, 사용자에게 보내지 않은 이유를 한 줄로 돌려준다. 읽기 함수를 주입식으로 받아 실패 경로를 테스트로 재현한다.
- 문서: `공용/게이트_실패시_열림_패턴.md`

### 2. Hive 암호화는 값만 암호화한다

- **사고**: 로컬 DB를 암호화했는데, 박스 파일을 열어 보니 키(개인정보로 만든 키)가 평문으로 남아 있었다.
- **규칙**: 개인정보를 키로 쓰지 않는다(해시로 바꾼다). 이미 설치된 앱의 평문 박스는 한 번만 옮기고, "옮김 완료" 표식은 맨 마지막에 쓴다.
- **코드**: 보안 저장소의 표식으로 분기해 평문 박스를 읽고, 지우고, 암호화 박스에 다시 쓴 뒤 표식을 남긴다.
- 문서: `공용/Hive_암호화는_값만_키는_평문_함정_평문박스_1회이전_패턴.md`

### 3. 공개 저장소에 내부 문서가 새지 않게

- **사고**: 내부용으로 쓴 문서에는 개인 경로와 프로젝트 사정이 섞여 있어, 그대로 공개하면 새어 나간다. 금지어 목록만으로는 아직 모르는 위험을 막지 못한다.
- **규칙**: 기본은 비공개. 금지어 검사를 통과하고, 사람이 읽고 승인한 문서만 공개한다. 승인은 그 시점 내용의 해시에 묶여, 원본이 바뀌면 자동으로 다시 비공개가 된다.
- **코드**: 이 저장소의 `강좌_허브/logic/publish_check.py`(판정), `강좌_허브/approve.py`(승인 기록). 이 저장소 자체가 그 규칙으로 만들어진 결과물이다.

## 결정 기록, 두 가지 예

규칙이 "무엇을 지킬지"라면, 결정 기록은 "왜 그렇게 정했고 무엇을 버렸는지"입니다.

### 뒤집은 결정 — AI 비서가 기억을 저장했다고 말만 할 때

- **문제**: 모델이 "저장했어요"라고 답하고 실제로는 저장 함수를 부르지 않는 일이 있었다.
- **처음 결정**: 프롬프트를 더 세게 썼다.
- **뒤집은 이유**: 모델이 지침을 어기면 같은 일이 다시 생긴다.
- **바꾼 것**: 매 턴 대화가 끝난 뒤 사실을 구조화 출력으로 뽑아 저장하고, 실시간 함수 호출은 보조로 내렸다. 구조화 출력은 호출을 건너뛰는 실패가 없고, 최악이어도 빈 목록이다.
- **검증**: 상용 AI 서비스 세 곳의 기억 구조를 비교해, 셋 다 같은 방식을 주경로로 쓴다는 것을 확인했다.

### 검증이 사고를 잡은 결정 — 레지스트리 변경 이력 DB

- **결정**: 여러 프로젝트 규칙을 관리하는 레지스트리에, 무엇이 언제 바뀌었는지 남기는 로컬 DB를 붙이고 바뀐 것만 알린다.
- **버린 대안**: 예약 작업 정리만(무엇이 바뀌었는지가 남지 않음), 파일 상시 감시(늘 켜 두는 앱이 아님).
- **검증에서 잡은 것**: 테스트가 만든 임시 레지스트리가 실제 이력 DB에 기록되고 있었다. DB가 처음 쓴 레지스트리만 받게 막고, 테스트는 기본으로 이력 기록을 끄게 고쳤다.

### 설계 난이도

프로젝트 카드마다 설계 난이도(1~5)를 매겼습니다. ★5 "운영 설계"는 ★4에 더해 배포, 여러 클라이언트가 같은 서버 규칙을 공유, 돈·한도, 인증·개인정보, 되돌리기 어려운 변경 중 셋 이상을 다룬 프로젝트입니다. 단계별 기준은 사이트 프로젝트 탭에 있습니다.

## 구성

| 경로 | 내용 |
|---|---|
| `공용/` | 패턴 문서(md). 공개 승인된 것만 |
| `강좌_허브/` | md → 규칙 JSON → 강좌 HTML 빌드, 금지어 검사, 해시 승인, 퀴즈 검사. 파이썬 표준 라이브러리만 사용 |
| `강좌_허브/퀴즈/` | 규칙별 문제(보기 고르기, 틀린 줄 찾기, 기준표 자기 채점) |
| `강좌_허브/프로젝트/` | 프로젝트 카드와 설계 전환점(JSON). 원본 결정 기록을 다시 써서 승인한 요약만 |
| `docs/index.html` | 빌드된 강좌 페이지(오프라인으로도 열림) |

## 직접 돌려 보기

```
cd 강좌_허브
python -X utf8 build.py      # 강좌.html 생성
python -m pytest -q          # 테스트
```

Windows에서는 `허브.bat`으로 빌드·승인 화면(tkinter)을 열 수 있습니다.
