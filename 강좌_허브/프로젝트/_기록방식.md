모든 프로젝트는 결정을 번호 붙은 기록으로 남깁니다. 코드는 "지금 무엇인가"만 보여 주고, 기록은 "왜 이렇게 됐나"를 보여 줍니다.

| 기호 | 뜻 | 언제 생기나 |
|---|---|---|
| **D** | 결정 (Decision) | 방향을 정했을 때. 무엇을, 왜, 무엇을 버렸는지 |
| **H** | 할 일 (TODO) | 결정은 했지만 아직 안 만든 것, 확인 못 한 것 |
| **P** | 정책 (Policy) | 여러 결정에 걸쳐 계속 지켜야 하는 규칙 |
| **O** | 미정 (Open) | 아직 정하지 못한 것과, 정하려면 무엇이 필요한지 |

**결정 하나의 모양**: 제목 한 줄(날짜, 커밋, 여러 안 중 무엇을 골랐는지) → 배경 → 결정 → 버린 대안과 이유 → 검증(테스트 수, 실측 수치) → 남은 틈.

**지우지 않고 뒤집습니다.** 결정이 틀렸으면 예전 번호를 고치지 않고 새 번호로 뒤집고, 어느 번호를 뒤집었는지 적습니다. 그래서 "처음엔 이렇게 생각했다가 무엇을 보고 바꿨나"가 남습니다.

**AI에게 맡기는 방식과 이어집니다.** 구조에 영향을 주는 작업은 AI가 여러 안을 나란히 내고 사람이 고릅니다. 고른 안이 그대로 D 기록의 "사용자 선택: 안 N"이 됩니다. 기록이 너무 길어지면 오래된 번호는 원문을 따로 옮기고 목차만 남깁니다.

**공개하는 범위**: 결정 기록 원문은 비공개입니다(외부 사정, 내부 경로, 결론 안 난 생각이 섞여 있음). 아래 프로젝트의 "전환점"은 원문에서 큰 결정만 골라 공개용으로 다시 쓴 요약이고, 원래 번호를 그대로 붙였습니다.
