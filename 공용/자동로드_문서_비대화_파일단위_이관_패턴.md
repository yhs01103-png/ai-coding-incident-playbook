# 자동 로드 문서 비대화 — 글자 수 한도와 파일 단위 이관 패턴

## 언제 여는가
CLAUDE.md처럼 세션마다 자동 로드되는 문서나 결정이력처럼 계속 누적되는 설계 문서가 한 파일로 수십만 자까지 커졌을 때, 또는 "줄 수 기준으로 레거시
섹션으로 옮기기"만으로는 총량이 줄지 않을 때. 규칙의 정식 위치는 `Plug_In_Global\.claude\설계도_이중계층_프로토콜.md` [15]이고, 이 문서는 그
절차를 실제로 돌릴 때 걸린 함정과 요령을 모은 것이다.

## 왜 줄 수 기준만으로는 안 되는가
- Read 툴은 한 번에 약 25,000토큰까지만 읽는다. 한글 문서는 줄 수보다 글자 수가 먼저 닿는다(9,315줄·468,897자 파일은 offset/limit 없이 못 읽었다).
- 같은 파일 안에서 최신→레거시 섹션 헤더만 옮기면 총량이 그대로라 컨텍스트 비용이 줄지 않는다. 자동 로드 문서에서는 이게 곧 매 세션 비용이다.
- "N줄을 넘으면 옮긴다"는 규칙만 있고 측정 시점이 없으면 실행되지 않는다(실측: 결정이력이 한 번도 분리되지 않고 3,178줄, 이후 9,315줄까지 누적).

## 절차 요약
1. 한도를 글자 수로 정해 프로젝트 README에 적는다(바이트가 아님). 절·결정을 추가한 작업 끝에 측정한다.
2. 이관 구간은 연속된 결정 블록 경계에서 자른다. 유효한 OPEN 목록처럼 살아 있는 항목이 섞인 비-결정 블록은 옮기지 않는다 — 구간 사이에 그런 블록이
   끼어 있으면 구간을 둘로 나눈다(예: ADR-21~76 / 77~133).
3. 원문을 스크립트로 새 파일에 **그대로** 복사하고(줄바꿈 보존: Python `newline=''`, 한글이면 `PYTHONUTF8=1`), 복사본에 원문 구간이 그대로 포함되는지 검사한 뒤에
   원본에서 지운다.
4. 원본에 남기는 것: 결정 문서는 번호·제목·"결정:" 한 줄(원문에서 자동 추출, 새로 쓰지 않음) + 이관 파일 경로. 자동 로드 규칙 문서는 "현행 규칙 요약" 절(규칙만,
   항목마다 원문 절·번호). 요약 문장은 사람이 새로 쓰는 부분이라 사용자 검토 대상이다.
5. 이관 파일 경로와 여는 조건을 프로젝트 README 참조 표에 한 줄씩 추가한다.

## 함정
- 이관 후에도 한도를 넘는다: ADR 본문만 옮겨서는 남은 OPEN 서술·오래된 변경이력이 큰 덩어리로 남는다. 이관 전에 블록별 글자 수를 재서 필요한 구간을 한꺼번에 정한다.
- 다른 문서가 "결정이력 N행"처럼 줄 번호로 인용하면 이관 뒤 어긋난다. 번호(ADR 등)로 인용하게 하고, 번호가 문서마다 다르면 결정이력 기준으로 맞춘다.
- 요약 절에 규칙을 옮겨 적을 때 원문에 없는 규칙을 만들지 않는다 — 원문의 "~할 것/반드시/⚠️" 문장을 근거로 뽑고 출처를 단다.
- 자동 로드 문서를 지우는 게 아니라 그 안의 "구현 서술" 구간만 옮기는 것이다. 현행 규칙(레이어 구조·인증·금지 사항 등)까지 같이 빠지면 규칙이 로드되지 않는다.
