# LLM 하루 예산 → 단위당 실측 → 절대 상한 + 무료 총량 패턴

2026-11-15 신설(RVS_App, 무료·게스트 체험을 여는 웹/앱의 비용 상한을 정하며 실측).

## 언제 쓰나

- 로그인 없이(또는 가입만으로) LLM 기능을 무료로 쓰게 열 참인데, 사용자 수가 늘면 비용이 얼마까지 갈지 몰라 불안할 때
- "하루 N원까지만" 같은 예산을 코드의 숫자(한도)로 옮겨야 할 때
- 요청 수 한도만 있고 비용 상한이 없어서, 모델 단가·재시도·생각 토큰이 바뀌면 지출이 조용히 달라지는 구조일 때

## 순서

1. **하루 예산을 먼저 정한다**(사람이 정함. 예: 5,000원).
2. **단위당 실비를 실측한다.** 추정하지 않는다. 격리한 서버 복사본(빈 DB 또는 개발 데이터 복사본, 임시 포트)에서 기능을 **실제 모델로 몇 번만** 돌리고, 공급자 콘솔의 사용량(요청 수·입력/출력 토큰)을 단가표에 곱해 `총비용 ÷ 소모된 단위`를 구한다.
   - 단위는 서버가 차감하는 과금 단위(기능마다 다름)다. 같은 기능도 모델 호출이 1~14번 들쭉날쭉(재시도·병렬)하므로 **호출 수가 아니라 단위당 평균**으로 센다.
   - 콘솔 그래프는 ±15% 오차가 있고 지연 집계(몇 시간)다 — 측정 뒤 한참 있다가 읽는다.
   - 측정 서버는 끝나면 폴더·프로세스·임시 포트를 지운다. 실제 키를 쓰되 값은 출력하지 않는다.
3. **절대 상한 = 하루 예산 ÷ 단위당 실비**(예: 5,000 ÷ 20원 = 250단위). 이 값을 **모든 무료 사용의 합계 상한**으로 둔다. 자동 계산이 어떻게 나와도 이 값을 넘지 못한다(`min`).
4. **자동 총량**(상한 아래에서 사용자 수에 맞춰 늘고 줄어드는 값) = `연동(가입 완료) 계정 수 × 계정당 무료 단위 × 여유(1.1) + 익명/게스트 몫`. 계정이 적을 때는 총량이 작아 상한까지 안 간다.
5. **결제로 산 횟수(지갑)는 총량 밖**이다 — 이미 돈을 낸 것이라 무료 총량이 차도 막히면 안 된다. 차감 순서 = 계정별 무료 → 무료 총량 → 지갑. 실패 환불 때는 무료로 쓴 단위만 총량에 돌려준다.
6. **공급자 쪽 2차 안전망**을 따로 건다 — 코드 상한은 "단위"를 세므로 재시도·생각 토큰·단가 인상(예: 정해진 날 2배)·키 유출(서버를 거치지 않는 호출)을 못 막는다. 월 지출 한도(콘솔, 지연·초과 가능)와 결제 예산 알림(알림만, 호출은 안 끊음). **하루 비용 한도는 공급자에 없다**(월 한도, 분·일 요청 수 한도만).
7. **재검토 날짜를 적는다**: 단가가 바뀌는 날(예: 2027-01-01 단가 2배 → 같은 예산이면 상한 125단위), 실사용 데이터가 쌓인 뒤.

## 함정

- 무료 등급 키로 이 실측을 하면 요청 수·토큰 한도에 걸려 평균이 왜곡되고, **무료 등급은 입력이 제품 개선에 쓰일 수 있다** — 사용자 개인 문장이 들어가는 서비스는 실사용자에게 열기 전에 결제(유료 등급)부터 연결한다.
- 월 한도를 건 프로젝트와 실제 키가 속한 프로젝트가 다른 경우가 있다(RVS: 한도는 새 프로젝트에 걸었는데 호출은 옛 키의 프로젝트에서 잡힘). 한도 화면의 Project를 키가 속한 곳으로 바꿔 확인한다.
- 선불 크레딧 결제 계정은 잔액이 0이면 유료 호출이 서비스 중단으로 이어질 수 있다 — 콘솔 상단 배너를 본다.
