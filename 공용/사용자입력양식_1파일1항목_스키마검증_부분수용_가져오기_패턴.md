# 사용자 입력 양식 — 1파일 = 1항목 + 스키마 검증 + 부분 수용 가져오기 (범용)

사용자가 여러 항목(계정, 설정, 상품 등)을 대화형 프롬프트가 아니라 **파일에 써서 한꺼번에 등록**하게 할 때의 설계.
처음엔 사람이 읽기 쉬운 txt 블록(`[이름]` + `PW:` 줄 …)으로 시작했다가, 라벨 오타가 조용히 무시되고 줄바꿈·혼합 문서에서 오파싱
위험이 있어 **스키마 있는 JSON, 파일 하나에 항목 하나**로 바꿨다.

## 설계 (한 줄 요약)

`양식 내보내기(빈 JSON N개, 번호 이어서)` → 사용자가 채움 → `가져오기`: 폴더의 모든 JSON을 읽어 **양식에 맞는 것만** 검증·미리보기·확인 후
저장 → 저장본 재검증 → (선택) 원본 삭제.

## 1. 한 파일에 여러 칸 vs 파일 1개당 1항목

| | 한 파일 여러 칸 | 1파일 1항목 (권장) |
|---|---|---|
| 작성 | 한 파일에서 연속 입력 | 파일마다 열어야 함 |
| 오류 영향 | 한 칸이 틀리면 파일 전체 보류 | 틀린 파일만 빠지고 나머지는 등록 |
| 오류 위치 | "칸 3번" | 파일 이름 |
| 가져온 뒤 정리 | 안 쓴 칸이 남은 채 파일 유지 | 쓴 파일만 삭제 |
| 평문 노출 | 모든 값이 한 파일에 | 분산 |

"한 번에 여러 개 입력하는 편의"는 **개수를 지정해 양식을 한꺼번에 만들어** 보완한다(`template 5` → 5개 파일).

## 2. 양식 내보내기 — 번호를 이어서, 기존 파일은 절대 건드리지 않는다

- 파일명 `새항목_양식_N.json`, N = 폴더의 기존 최대 번호 + 1부터. 이미 있는 양식을 덮어쓰거나 "이미 있음"으로 거부하지 않는다
  (작성 중인 내용 보호 + 중복 생성 가능).
- 양식에는 `schema`(식별자+버전, 예: `vault-entry/1`)와 `_help`(사용법 한 문장)를 넣고 필드는 빈 문자열로 둔다.
- **파일 이름은 사용자가 바꿔도 된다** — 가져오기는 이름이 아니라 내용(schema)으로 판별한다.

## 3. 가져오기 — 파일 상태를 4가지로 분류

| 상태 | 판별 | 처리 |
|---|---|---|
| ok | schema 일치 + 필수값 충족 | 등록 대상(미리보기에 표시) |
| blank | schema 일치 + 모든 필드 비어 있음 | 조용히 건너뜀, 개수만 표시 |
| foreign | JSON이지만 schema가 없거나 다름 | "양식이 아니라 건너뜀" 안내 (다른 용도의 JSON·옛 버전 양식) |
| error | schema 일치 + 검증 실패, 또는 JSON 문법 오류 | **파일 이름과 사유를 빨간색으로** 보여 주고 그 파일만 제외 |

error 검증 항목: **알 수 없는 키**(오타: `password` → 허용 키 목록을 같이 출력), **문자열이 아닌 값**(따옴표 없는 숫자 → "따옴표로 감싼 문자열이어야 함"),
필수값(이름) 누락, 둘 중 하나는 필요한 필드(id/pw) 둘 다 없음. 파일 안에서는 전부 아니면 전무, **파일 사이에서는 부분 수용**.

## 4. 저장 전·후 안전장치

1. **미리보기**: `가져올 항목 N개 (신규 a / 덮어쓰기 b)` + 항목별 `[신규|덮어쓰기] ← 파일명`. `yes`가 아니면 아무것도 저장하지 않는다(취소 시 목록이
   그대로인지 테스트).
2. **서로 다른 파일에 같은 이름**이 있으면 전체 거부(어느 쪽이 이길지 추측하지 않는다).
3. **덮어쓰기 시 비워 둔 설명/키워드는 기존 값 유지** — 비밀 값은 양식 내용이 그대로 우선.
4. **저장 후 다시 읽어** 복호화/조회한 값이 양식과 같은지 검증하고, 실패하면 양식 파일을 건드리지 않은 채 에러.
5. 양식 원본(평문)은 **삭제 여부를 한 번 더 `yes`로** 묻는다 — 기본값은 유지.

## 5. 대화형 메뉴와 함께 쓸 때

- 대화형 메뉴의 "항목 추가/삭제"를 걷어내고(프롬프트로 한 개씩 입력하는 건 불편하고 오타 위험이 크다) 양식 경로로 일원화해도 된다. 삭제처럼
  가끔 쓰는 기능은 명령줄(`rm <번호>`)로만 남긴다.
- **엔터는 진행/확정**에 쓰고, 이동은 메뉴에 `이전`·`홈` 번호를 따로 둔다 — 엔터를 "돌아가기"로 쓰면 확정과 충돌한다. 하위 입력 단계에서도
  `이전`/`홈` 단어를 받는다(비밀 입력 단계는 가릴 수 없으니 `Ctrl+C` 안내).
- 메뉴 번호를 바꿀 때는 **다른 스크립트·문서·안내 문구에 박힌 번호**를 같이 갱신한다(예: "hub → 0 → 4" 안내가 옛 번호로 남는 사고).

## 체크리스트

- [ ] schema 식별자 + 버전, 알 수 없는 키/타입/필수값 검증, 오류는 파일명 + 사유
- [ ] foreign(다른 JSON)·blank(빈 양식)는 오류가 아닌 조용한 건너뜀
- [ ] 파일명 변경 허용, 번호 이어서 생성, 기존 양식 비침범
- [ ] 미리보기 → 확인 → 저장 → 재검증 → 삭제 확인, 취소 시 무변화 테스트
- [ ] 이름 중복(파일 간) 거부, 덮어쓰기 시 비어 있는 비밀 아닌 필드는 기존 값 유지
- [ ] 여러 줄 값(키 파일 등)이 양식 왕복에서 보존되는지 테스트

**실측 출처**: 개인 보안정보 폴더(`coding_admin`) 암호화 저장소 — 가져오기 양식을 txt 블록 → 다중 칸 JSON → 1파일 1항목 JSON으로 세 번
바꾸며 확정한 설계(2026-10-20).
