# 실제 시계로 만료를 판정하는 코드를 고정 날짜 픽스처로 테스트하면, 날짜가 지나는 순간 조용히 깨진다

## 실측 사례 (poker_app/server, 2026-09-29, ADR-193 후속)

회사 대전 도전에 "응답 기한 2일, 지나면 자동 거절"을 넣었다. 기한 판정은 `datetime.now(timezone.utc)`(실제 시계)로 한다.
그런데 이미 있던 테스트 헬퍼가 도전을 `created_at="2026-09-28T00:00:00+00:00"`(작성 당일 고정값)으로 만들고 있었다.
작성한 날에는 전부 통과하지만, 이틀이 지나면 그 도전들이 전부 "만료"로 판정돼 수락·거절 테스트가 일제히 깨진다 —
코드는 그대로인데 달력 때문에. 기한 기능을 넣으면서 헬퍼를 `now - age` 기준으로 바꿨다(`age_hours=0` 기본, 만료 경계
테스트는 47시간/49시간).

## 패턴

- 실제 시계를 읽는 판정(만료·쿨다운·"오늘"·시즌 경계)을 새로 넣을 때, 그 판정을 거치게 되는 **기존 테스트 픽스처의 날짜
  리터럴**을 먼저 찾는다(`grep -n "20[0-9][0-9]-" tests/`).
- 픽스처는 "지금 기준 상대값"으로 만든다(`now - timedelta(...)`). 경계 테스트는 경계 양쪽(예: 기한 −1시간/+1시간)으로.
- 절대 날짜가 꼭 필요하면(과거 시즌 표시처럼 "현재와 다르기만 하면 되는" 값) 판정이 실제 시계와 무관한지 확인한다 —
  poker_app의 `season_marker` 비교는 저장된 값끼리 비교라 고정 리터럴이어도 안전했다.
- 시계를 주입 가능하게(`now=` 인자) 하면 가장 확실하지만, 파이프라인 전 경로에 인자를 뚫기 부담이면 위 상대값 픽스처로 충분.
