# 소비형 선충전 지갑 + 스토어 결제 + 환불 회수 패턴

구독 대신 "횟수 묶음"을 사서 쓰는 구조(AI 호출권, 코인류)를 서버 지갑으로 만들 때의 순서와 함정. RVS_App 실측(2026-11-08~09).

## 1. 지갑은 서버가 채운다 — 클라이언트 토큰은 믿지 않는다
- 흐름은 **스토어 결제 → 서버가 스토어에 직접 확인 → 지갑 충전 → 소비(consume)** 순서다. 클라이언트는 구매 토큰만 서버로 보낸다.
- 충전은 구매 토큰의 해시를 `ref`(유일 키)로 원장에 남겨 **같은 구매는 한 번만** 반영한다. 재시도·중복 호출이 안전해진다.
- 구매 토큰을 계정에 묶어(다른 계정이 쓰면 409) 영수증 재사용을 막는다.

## 2. 소비 실패는 충전을 되돌리지 않는다
- 충전 뒤 소비(consume)가 실패하면 **503으로 재시도를 요청**한다. 지갑은 이미 채워져 있고, 다시 부르면 충전은 건너뛰고(ref 중복) 소비만 다시 시도한다.
- 클라이언트는 결제 plugin의 자동 소비를 끄고(`autoConsume:false`) 서버 확인이 끝난 뒤에만 완료를 알린다. 앱을 켤 때 끝나지 않은 구매를 다시 서버에 확인시킨다.

## 3. 차감은 낸 곳으로 돌려준다
- 차감 순서(전체 예산 → 하루 무료 → 지갑)가 있으면 **요청마다 지갑에서 낸 단위 수를 기억**해 두고, 실패·취소 환불은 지갑 몫부터 되돌린다. 안 그러면 무료분만 늘어나거나 지갑이 샌다.
- 잔액은 `CHECK(balance>=0)` + `UPDATE … WHERE balance>=n`의 원자 차감으로 지킨다(읽고 쓰기 금지).

## 4. 환불 회수 — 스토어가 정하고, 서버는 따라간다
- 환불 결정은 스토어(사용자 48시간 요청·카드 분쟁 포함)가 하므로 "N일 이후엔 환불 불가"는 **서버 규칙이 아니라 운영·약관 정책**이다. 서버는 환불된 구매를 **시점과 무관하게** 거둔다(돈은 나갔는데 횟수가 남는 걸 막는다).
- 하루 한 번 환불 목록(Play `purchases.voidedpurchases`, `type=0`)을 조회해 토큰 해시로 원장의 충전 행을 찾아 거둔다. 실시간이 필요하면 RTDN(Pub/Sub)을 같은 회수 함수 앞에 얹는다.
- **가능한 만큼만 거두고 0에서 멈춘다** — 음수 잔액을 허용하려면 스키마 제약을 바꿔야 하고, 이미 쓴 몫은 사실상 회수 불가라 소액 소비형에선 0 멈춤이 단순하다.
- 거둔 기록도 `void:<충전 ref>`로 원장에 남겨 한 번만 거둔다(거둘 게 0이어도 행을 남긴다). 이후 새로 채운 횟수는 다시 거두지 않는다.
- 결제 검증이 설정되지 않은 서버(개발 등)에서는 회수를 조용히 건너뛰고, 그 밖의 실패는 서버를 멈추지 않게 로그만 남긴다.

## 5. 함정
- Google Play 소비형은 구독용 v2 조회가 아니라 `purchases.products.get`(구매 완료 `purchaseState==0`, 소비됨 `consumptionState==1`)이다. 필드가 다르다.
- Flutter 위젯 시험에서 `defaultTargetPlatform`은 기본 android라 결제 지원으로 잡힌다 — 미지원 분기는 가짜 결제기를 주입해 시험한다.
- 상품 id·횟수·가격 같은 운영 값은 개발 폴더엔 중립(빈 목록), 서비스 폴더에서만 채워 두 폴더가 어긋나지 않게 한다(`개발_서비스_폴더_분리_운영_패턴.md`).

## 6. 등급·구독을 지갑으로 갈아탈 때
- 돈의 기준을 "호출 횟수" 하나로 두면 기능 잠금(`require/enabled`)과 등급별 한도는 둘 다 필요 없다. **잠금 호출을 먼저 걷고**, 요청 신원(소유자·등급)이 계정 등급을 읽지 않게 해 한도를 하나로 맞춘다. 계정의 등급 열은 지우지 않고 읽지만 않으면 스키마 변경 없이 끝난다.
- 등급 전용 모듈·라우트·시험은 삭제 대신 `_legacy/`로 옮기고 README에 되살리는 방법을 적는다. 시험은 "옛 잠금 값·계정 등급이 있어도 동작과 한도가 같다"로 먼저 쓴다.
- ContextVar(요청 신원)는 `asyncio.run` 안에서 심으면 밖에서 안 보인다 — 시험은 같은 코루틴 안에서 확인한다(안 그러면 변경 전에도 통과해 버린다).
- 다음 수익 후보(예: 무료 한도 초과 슬롯 판매)는 수요 지표(한도 도달 비율 등)를 정해 두고, 지표가 나오기 전엔 상품·화면을 만들지 않는다.
