# 업로드/수신 파일의 진짜 유형은 확장자가 아니라 매직바이트로 확인 (범용)

사용자가 업로드하거나 외부에서 들어오는 파일을 다루는 모든 기능(파일 업로드
API, 파일 뷰어/변환기, 첨부파일 처리 등)에 적용되는 보안 패턴.
FileLens_App 실측에서 정리(2026-11-18 프로젝트 폴더에서 공용으로 이동).

## 문제 — 확장자는 사용자가 마음대로 붙인 라벨일 뿐

파일 확장자(`.jpg`, `.pdf` 등)는 파일 내용과 무관하게 얼마든지 바꿔 붙일 수
있다 — 확장자만 보고 처리 방식을 정하면, 실행파일에 `.jpg`를 붙여 이미지
처리 파이프라인에 밀어넣는 식의 위조 공격에 그대로 노출된다.

## 해법 — 파일 헤더(매직바이트)로 실제 유형을 판별하고, 확장자와 대조

```python
def detect_real_type(file_bytes: bytes) -> str:
    if file_bytes[:8] == b'\x89PNG\r\n\x1a\n':
        return 'png'
    if file_bytes[:3] == b'\xff\xd8\xff':
        return 'jpeg'
    if file_bytes[4:8] == b'ftyp':  # MP4/MOV 계열
        return 'mp4'
    if file_bytes[:4] == b'%PDF':
        return 'pdf'
    # 바이너리 시그니처 없는 텍스트류는 휴리스틱(UTF-8 디코딩 성공 여부 등)
    return _detect_text_heuristic(file_bytes) or 'unknown'


declared_ext = filename.rsplit('.', 1)[-1].lower()
actual_type = detect_real_type(file_bytes)
if declared_ext != actual_type:
    log_security_event("확장자_위변조_의심", filename=filename,
                        declared=declared_ext, actual=actual_type)
    # 여기서 곧바로 거부할지, 실제 유형 기준으로만 처리할지는 위험도에 따라 결정
```

핵심은 **불일치를 발견했을 때 조용히 확장자 쪽으로 맞춰버리지 않는 것** —
확장자와 실제 내용이 다르다는 사실 자체를 보안 이벤트로 로그에 남긴다.
이후 그 파일을 거부할지, 실제 감지된 유형 기준으로 처리를 계속할지는
그 기능의 위험도(실행 가능한 파일을 다루는지, 단순 뷰어인지)에 따라
달리 정한다.

## 적용 범위

이미지/동영상/문서처럼 확장자 위조가 실제 보안 문제로 이어질 수 있는 모든
업로드 기능에 적용한다. 사용자가 자기 컴퓨터 안에서만 쓰는 로컬 도구(외부
업로드가 없는 경우)에는 우선순위가 낮다.
