# LLM JSON 응답이 가끔 안 읽힐 때 — JSON 응답 모드 + 내용 없는 진단 로그 패턴

## 문제

LLM에게 "아래 JSON 형식으로만 답하라"고 시키고 응답에서 첫 `{`~마지막 `}`를 잘라 `json.loads` 하는 구조는 대부분 돌아간다.
그런데 **가끔 한 번씩** 못 읽고 폴백("결과를 만들지 못했어요")으로 떨어진다. 다시 하면 정상이라 재현이 안 되고,
로그에는 원문을 남기지 않는 원칙(개인정보) 때문에 "못 읽었다"만 남아 원인이 갈리지 않는다.

**실측(RVS_App, 2026-11-02)**: gemini-3.6-flash 역산 결과 생성이 실기기 2번 중 1번 실패. 로그 "길이 1373, `{` 시작 False, `}` 끝 False".
같은 프롬프트를 직접 보내 응답 모양을 보려 했지만 그날 그 모델의 **하루 한도가 이미 소진**돼 재현 불가.
예비 모델(3.1-flash-lite)은 9번 모두 맨 JSON — 모델마다 버릇이 다르다.

## 흔한 원인(모양으로 가른다)

| 로그 모양 | 원인 후보 | 잘라 읽기가 견디나 |
|---|---|---|
| 시작이 `` ` ``(펜스), 끝도 `` ` `` | 코드 펜스(```json … ```) | 견딤 — 첫 `{`~마지막 `}` |
| 앞에 설명 문장, 뒤에 `}` | 머리말 | 견딤 |
| `}`로 안 끝나고 `finishReason`이 STOP 아님 | 길이 한도·안전 차단으로 잘림 | 못 견딤 |
| 모양은 멀쩡한데 `JSONDecodeError` | **문자열 안 큰따옴표 미이스케이프**(`"팀장이 "알겠어"라고 했다"`), 끝 쉼표 | 못 견딤 |

한국어 결과 문장은 인용("…라고 말한다")이 잦아 마지막 줄이 특히 흔하다.

## 해결

1. **모델의 JSON 응답 모드를 켠다.** Gemini는 `generationConfig.responseMimeType = "application/json"`(OpenAI는 `response_format={"type":"json_object"}`).
   모델이 유효한 JSON만 내므로 펜스·머리말·미이스케이프가 한꺼번에 사라진다. 프롬프트의 "JSON으로만 답하라"와 파서는 그대로 둔다(이중 안전).
   - Gemini는 **검색 그라운딩 도구와 JSON 모드를 같이 못 쓴다** — 공용 호출 함수에서 `use_search`면 끈다.
   - 공용 호출 함수에 **선택 인자**(`json_mode=False`)로 넣고 실패가 확인된 호출부터 켠다. 전체 기본값으로 바꾸면 평문 응답(해설 등)이 깨진다.
2. **진단 로그는 모양만, 내용은 빼고.**
   - 공용 호출 함수: `finishReason`이 STOP이 아니면 이유와 길이만 경고.
   - 파서 실패 지점: 길이, `{` 시작·`}` 끝, 펜스로 시작하는지, `JSONDecodeError`의 **종류와 위치**(`"Expecting ',' delimiter @812/1373"`) — `e.msg`·`e.pos`만 쓰고 `e.doc`은 쓰지 않는다.
   - 다음 실패 한 번으로 위 표의 어느 칸인지 갈린다. 로그에 원문 조각이 없는지 시험으로 고정한다(caplog에 비밀 문자열이 없음을 assert).
3. **재현 조사는 한도를 쓴다.** 응답 모양 조사(같은 프롬프트 n번)는 생성 호출이라 무료 등급이면 그날 서비스·측정 몫을 먹는다.
   조사 스크립트는 원문을 출력하지 않고 `finishReason`·parts 수·앞뒤 몇 글자·파싱 성공 여부만 찍는다.

## 함정

- **시험 가짜 함수가 새 인자에 깨진다.** `monkeypatch`로 바꿔 끼운 가짜가 `async def fake(prompt, temperature=None)`처럼 좁게 받으면
  호출부에 `json_mode=True`를 더하는 순간 TypeError로 수십 개가 실패한다. 가짜는 처음부터 `**_kw`로 받게 쓴다(RVS: 21개 고침).
- 인자를 더하는 대신 "프롬프트에 'JSON으로만' 문구가 있으면 자동으로 JSON 모드"는 문구가 호출마다 달라(“JSON 하나만”, “JSON 객체 하나만”) 깨지기 쉽다 — 명시 인자가 낫다.
- 실패 재현 없이 고친 것은 **"실모델 확인 대기"로 남긴다.** 예비 모델에서 잘 된다고 실패한 모델에서 해결됐다는 증거는 아니다.

## 체크리스트

- [ ] JSON을 기대하는 호출 중 실제로 실패가 난 호출에 JSON 모드를 켰는가(검색 도구와 함께 쓰는 호출은 제외)
- [ ] `finishReason`·JSON 오류 종류·위치가 로그에 남고 원문은 안 남는가(시험으로)
- [ ] 시험 가짜 함수가 `**_kw`를 받는가
- [ ] 한도가 풀린 날 실패 모델로 다시 확인했는가 — 전까지는 "확인 대기"
