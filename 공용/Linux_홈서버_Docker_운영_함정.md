# Linux 홈서버 Docker 운영 함정 (범용)

개인 홈서버(Ubuntu 등)에 Docker로 여러 서비스를 올려 운영할 때 반복되는 함정.
방화벽으로 막았다고 생각했는데 안 막혀 있거나, 셸에서 따옴표로 감쌌는데
비밀번호가 계속 안 맞는 경우가 이 문서에 해당한다. 특정 프로젝트에
종속되지 않음.

## 함정 1 — UFW로 포트를 막아도 Docker가 `-p host:port`로 발행한 포트는 안 막힘

**증상**: `sudo ufw delete allow 5432` 같은 명령으로 방화벽 규칙을 지웠는데도,
외부에서 그 포트로 여전히 접속이 된다.

**원인**: Docker는 컨테이너를 `-p 5432:5432`(호스트의 모든 인터페이스에 바인딩)로
띄우면, UFW(iptables의 `INPUT` 체인)와 **별개로** 자기 자신의 iptables 규칙
(`FORWARD`/`DOCKER` 체인)을 직접 추가한다. UFW는 `INPUT` 체인만 다루는데,
Docker로 포워딩된 트래픽은 `FORWARD` 체인을 타기 때문에 UFW 규칙이 아예
적용되지 않는다 — 이건 잘 알려진 Docker+UFW 조합의 구조적 문제지, 설정
실수가 아니다.

**해결**: UFW 규칙을 만지지 말고, **컨테이너 자체를 재생성**해서 호스트
바인딩을 로컬로 제한한다:
```bash
# 이전: -p 5432:5432                (모든 인터페이스에 노출 — 사실상 인터넷에 열림)
# 이후: -p 127.0.0.1:5432:5432      (로컬 전용 — 외부에서 물리적으로 접근 불가)
docker rm -f <컨테이너명>
docker run -d --name <컨테이너명> \
  -p 127.0.0.1:5432:5432 \
  -v <기존 볼륨>:<컨테이너 내부 경로> \
  <이미지>
```
외부에서 그 포트로 원격 접속이 필요하면(예: 클라우드에 배포된 앱이 접속해야
하는 경우) SSH 역터널로 우회한다 —
[클라우드_홈서버_SSH역터널_배포_트러블슈팅.md](클라우드_홈서버_SSH역터널_배포_트러블슈팅.md)
참고. 볼륨을 그대로 유지하면 컨테이너 재생성으로 데이터 유실은 없다.

**주의**: 이 우회는 `-p` 방식(포트 발행)에만 해당한다. `--network host`로 띄운
컨테이너는 일반 프로세스와 동일하게 UFW `INPUT` 체인을 그대로 적용받는다 —
방화벽 규칙이 정상 작동하는지는 컨테이너의 네트워크 모드에 따라 다르다는 걸
확인하고 판단해야 한다.

## 함정 2 — `docker run -e PASSWORD='...'`에서 `!`가 든 비밀번호가 bash 히스토리 확장으로 깨짐

**증상**: `docker run -e POSTGRES_PASSWORD="Abc!123"` 처럼 따옴표로 감쌌는데도,
나중에 그 비밀번호로 로그인이 안 된다.

**원인**: 대화형 bash(스크립트 파일이 아니라 터미널에 직접 타이핑하는 경우)는
기본적으로 **히스토리 확장**(`!`)이 켜져 있다. 이건 따옴표 처리보다 먼저
일어나는 별개의 파싱 단계라, **큰따옴표 안에 있어도** `!`가 히스토리 확장
문법으로 해석돼 의도한 것과 다른 문자열이 실제로 전달된다(예: `!123`이
"히스토리 123번 명령으로 치환 시도" 취급됨). 히스토리 확장을 막는 따옴표는
작은따옴표와 백슬래시뿐이다 — 작은따옴표로 감쌌는데도 깨졌다면 중간에 다른
셸·스크립트·SSH 명령 문자열을 한 번 더 거치며 큰따옴표 문맥이 된 경우를
의심한다(2026-11-18 정정: 이전 판은 "작은따옴표 안에서도 확장된다"고 적었으나
bash 동작과 다르다).

**해결 (택1)**:
- **컨테이너 실행 후 앱 자체 도구로 비밀번호를 재설정**한다 — 예를 들어
  Postgres라면, 로컬 소켓 접속은 트러스트 인증이라 비번 없이 들어가지므로:
  ```bash
  docker exec -it <컨테이너명> psql -U <유저> -d <db명>
  # psql 프롬프트 안에서(bash 파싱을 거치지 않음, 안전):
  ALTER USER <유저> WITH PASSWORD '특수문자!포함비번';
  ```
- **또는 애초에 특수문자를 피한다** — 영숫자로만 구성된 hex 문자열 등으로
  비밀번호를 정하면 이 함정 자체가 발생 안 하고, DB 접속 URL 문자열
  (`postgresql://user:pass@host/db`)에 넣을 때 `#`/`@` 등 다른 특수문자가
  구분자와 충돌하는 별개의 문제도 같이 피할 수 있다.
- **또는 그 세션만 히스토리 확장을 끈다**: `set +H` 실행 후 명령어 실행(다시
  켜려면 `set -H`).

이 문제는 `docker run` 뿐 아니라 `!`가 든 값을 셸 명령행에 직접 넣는 모든
경우(다른 CLI 도구의 `-e`/`--password` 류 옵션 포함)에 동일하게 재현된다.
