# 사용자를 대신해 행동하는 자율 에이전트 루프의 안전장치 체크리스트 (범용)

앱이 사용자를 대신해 연속으로 여러 행동을 자동 수행하는 모든 기능(화면
자동조작, 자동화 매크로, 반복 API 호출 루프 등)에 적용하는 안전 체크리스트.
AllAd Launcher(AllAd_Launcher, 접근성 서비스 기반 앱 자동조작 에이전트) 실측 사례에서 정리
(2026-08-19). Claude Code/IDE용 AI 에이전트의 "MCP 쓰기권한 거버넌스"
(`AI_에이전트_MCP_쓰기권한_거버넌스_패턴.md`)와 결이 같지만, 이 문서는 **일반
사용자를 대신해 화면/외부 앱을 조작하는 소비자용 에이전트**가 대상이라 그
문서와 별개로 둔다.

## 체크리스트 4가지

1. **되돌리기 어려운 행동은 무조건 확인 게이트를 거친다, 예외 없음.**
   결제/삭제/발송처럼 "실행하면 되돌릴 수 없는" 행동으로 분류되는 액션은
   자동/신뢰 모드 여부와 무관하게 항상 사용자 확인을 막는 다이얼로그를
   거친다 — 우회 경로를 아예 만들지 않는다.

2. **루프가 도는 동안 언제든 누를 수 있는 중단 버튼이 항상 화면에 보인다.**
   "실행 취소"가 아니라 "지금 당장 멈추기" — 루프 시작 후 사용자가 마음이
   바뀌었을 때 즉시 멈출 수 있는 경로가 실행 내내 사라지지 않아야 한다.

3. **같은 행동이 N회 연속 실패하면 자동으로 멈춘다(기본값 3회).**
   "안 되는 걸 계속 시도"는 사용자가 지켜보고 있지 않을 때 특히 위험하다 —
   같은 액션이 연속으로 실패를 반복하면 사람 개입 없이도 루프 자체가
   스스로 멈춘다. 임계값은 상황에 맞게 조정 가능하되, 기본값이 "무한
   재시도"면 안 된다.

4. **비용이 저렴한 경로를 기본값으로, 비싼/위험한 경로는 사용자가 명시적으로
   연 것으로 취급한다.** 예: 화면 요소 트리 분석(저렴)을 기본으로 쓰고,
   비전 모델 호출(비쌈)이 필요한 케이스는 사용자가 그 기능의 자격증명을
   등록해야만 활성화 — **자격증명 등록 자체가 "이 비싼 경로를 써도 된다"는
   동의 신호를 겸하게** 설계하면 별도 동의 UI 없이도 opt-in이 구조적으로
   보장된다.

## 개발 측 부가 원칙 — 한 라운드 = 한 기능 = 한 커밋

이 종류의 기능을 개발할 때는 라운드당 기능 하나씩만 커밋한다 — 자율 루프
로직은 한 라운드에서 여러 걸 한꺼번에 바꾸면 "이번 변경 중 뭐가 이 이상행동을
일으켰는지" 역추적이 어렵다. 문제가 생기면 커밋 하나만 되돌리면 바로 이전
안전 상태로 복구되게 만드는 게, 사후 디버깅 비용을 줄이는 것보다 더 중요한
안전장치다(자율 행동 루프는 실제 사용자 환경에 부작용을 남기므로, "일단
배포하고 다음에 고치자"의 대가가 일반 버그보다 크다).
