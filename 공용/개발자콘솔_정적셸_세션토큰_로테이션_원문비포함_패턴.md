# 개발자 콘솔 — 정적 화면 껍데기 + 로그인 뒤 요청마다 바뀌는 세션 토큰 + 사용자 원문 비포함 (범용)

운영자(개발자)가 서버 상태·사용량·지표를 볼 화면을 서버에 붙일 때의 패턴. 메인 앱 UI에 탭으로 넣지 않고 "주소를 아는 사람만" 여는 별도 페이지로 둔다. Lazzy(Jarvis)의 `dev_console.html`, poker_app의 `/devconsole/*`, JudgeCal의 devconsole에서 반복된 구조를 RVS_App(2026-10-23)이 한 번 더 정리했다.

## 1. 구조 — 껍데기는 공개, 데이터는 잠금

- **화면 껍데기**(`GET /dev-console`)는 정적 HTML+JS 한 장이다. DB 접근이 없고 민감한 것이 없으니 인증 없이 서빙한다. 브라우저 주소창에 URL을 치는 일반 GET에는 커스텀 헤더를 못 붙이기 때문이다. 캐시는 `no-store`.
- **데이터 라우트**(`/devconsole/*`)는 전부 읽기 전용 GET이고, 로그인한 세션 토큰이 있어야 한다. 쓰기·삭제 라우트는 만들지 않는다 — 조회 도구가 파괴 수단이 되지 않게.
- **꺼진 기능은 404**: 마스터 비밀 환경변수가 비어 있으면 화면·로그인·데이터가 전부 404를 돌려준다(401이 아니라). 배포 환경에서 값을 넣기 전까지는 존재 자체를 알리지 않는다. 라우터는 항상 등록하고 라우트마다 "켜져 있는가" 의존성을 건다(조건부 등록이면 테스트가 어렵다).

## 2. 토큰 — 마스터 비밀은 로그인에만, 세션 토큰은 수시로 바뀐다

고정 토큰 하나를 헤더에 싣는 방식은 유출되면 영구적이다. 아래처럼 바꾼다.

- **마스터 비밀**(환경변수)은 `POST /login`에서 한 번만 쓴다. 데이터 라우트에서 마스터 비밀을 보내도 통하지 않게 한다(테스트로 고정).
- 로그인하면 **세션 토큰**(`secrets.token_urlsafe(32)`)을 준다. 서버는 해시(sha256)만 메모리에 둔다.
- **매 요청 교체(rotate)**: 통과한 응답마다 헤더(`X-Dev-Token-Next`)로 새 토큰을 주고, 쓴 토큰은 **유예 시간(30초)** 뒤 죽게 한다. 유예가 없으면 화면이 요청 두 개를 동시에 보낼 때 늦게 도착한 쪽이 401을 맞는다.
- **유휴 만료**(마지막 사용 후 15분)와 **절대 수명**(로그인 후 8시간 — 계속 써도 만료)을 둘 다 둔다. 교체해도 `login` 시각은 물려받게 해야 절대 수명이 늘지 않는다.
- **로그인 실패 제한**: 같은 IP에서 10분에 5번 틀리면 10분 잠금(429+`Retry-After`). 프록시 뒤에서는 `X-Forwarded-For`의 마지막 항목을 쓴다(앞쪽은 위조 가능).
- **로그아웃 두 종류**: 내 세션만 / 전체. 열려 있는 콘솔 세션 수는 런타임 화면에 보여 준다(교체 직전 토큰은 세지 않는다).
- 화면은 토큰을 `sessionStorage`에만 둔다(탭을 닫으면 사라짐, `localStorage`는 쓰지 않는다). 응답을 받을 때마다 갈아 끼우고, 401이면 로그인 화면으로.
- 한계: 세션을 프로세스 메모리에 두면 서버 재시작 때 모두 로그아웃되고, 서버가 여러 개로 늘면 서버마다 따로다. 그때는 공유 저장소가 필요하다.

## 3. 응답에 사용자 원문을 넣지 않는다

콘솔은 운영자 도구지만 사용자 글을 볼 이유는 없다. **건수·비율·시각·지연·분포만** 낸다.

- 집계 쿼리는 원문 컬럼(상황·행동·결과 문장, 프로필, 이메일)을 SELECT하지 않는다. 계정은 개수와 티어만.
- "최근 사건" 로그도 종류+숫자 필드만 받는 함수로 만든다(문자열 필드는 걸러냄).
- **테스트로 고정**: 특이한 문자열("비밀스러운상황문장")로 데이터를 만들고, 모든 콘솔 응답을 JSON으로 합쳐 그 문자열이 없는지 `assert not in`.
- 표가 아직 없는 첫 사용 전에도 빈 값으로 열리게 한다(`no such table`이면 빈 결과) — 콘솔이 첫 장애 때 아무것도 못 보여 주면 소용없다.

## 4. 런타임 카운터

프로세스 메모리 카운터(`Counter` + 최근 사건 `deque(maxlen=50)`)를 둔다: LLM 시도 성공/실패/429·평균 지연, 재시도·빈 응답·실패 횟수. 기존 계측 함수(요청 컨텍스트가 있어야 기록하던 것)는 **컨텍스트 앞에서** 서버 전체 카운터에도 쌓는다. 기록 함수는 예외를 삼켜 요청을 깨지 않게 한다. 재시작하면 0이라는 점을 화면에 적어 둔다.

## 5. 함정

- 사용 기록 같은 **날짜 문자열 비교**는 형식이 같아야 한다 — SQLite `datetime('now')`는 공백 구분인데 저장값은 `T` 구분이면 문자열 비교가 어긋난다. 비교 기준값은 저장한 쪽과 같은 함수로 만들어 파라미터로 넘긴다.
- 서로 다른 DB 파일(사용량·계정·본 DB)을 합치는 집계는 각자 열어 파이썬에서 합친다. 한 연결로 ATTACH하지 않는다.
- 화면 JS를 만들었으면 최소한 `node --check`로 구문 검사를 하고, 가능하면 실제 브라우저로 로그인→탭 전환→토큰 교체를 눈으로 본다(RVS는 브라우저 확장이 연결되지 않아 구문 검사+로컬 서버 호출 확인까지만 했다 — 문서에 "눈으로 못 봄"이라고 적었다).
- 마스터 비밀을 데이터 라우트에도 받아 주는 "편의" 경로를 남기지 않는다. 그러면 로테이션이 의미 없어진다.

## 구현 사례

- RVS_App: `server/routers/devconsole.py`(화면·로그인·데이터), `devtokens.py`(세션 토큰 교체·잠금), `devstats.py`(집계), `runtime_stats.py`(카운터), `static/dev_console.html`. 시험: `server/test_forecast.py` 하단 devconsole 5개(404/로그인/교체와 만료/잠금과 로그아웃/원문 비포함).
- 원형: Lazzy_App_OS_Monorepo `server/api/static/dev_console.html`(껍데기 공개+게이팅된 API 호출), poker_app `devconsole.py`(토큰 보호 라우터).
