# 운영 값 덮어쓰기 파일에 새 키를 안 넣으면 조용히 다른 값으로 떨어진다

2026-11-15 신설(RVS_App — 게스트 등급을 만들고 승격하다 게이트가 잡음).

## 증상

- 개발 폴더에서는 새 기능(예: 등급 `guest`의 한도 2회)이 시험까지 통과하는데, 서비스 폴더로 승격하는 검증에서 "제약 짝 테스트"가 실패한다.
- 안 잡혔다면: 운영에서 새 등급이 **기본 등급 값으로 떨어져** 의도(2회)가 아니라 10회가 나갔을 것이다. 에러가 없다.

## 원인

- 구조: `rules.py`(중립/기본값) 위에 서비스 폴더만 가진 `rules_values.py`가 **같은 이름의 표를 통째로 교체**한다(`globals()[name] = value`).
- 표는 `{"free": .., "paid": ..}`처럼 키가 등급이라, 새 키(`guest`)를 `rules.py`에만 넣으면 교체 뒤의 표에는 그 키가 없다. 조회가 `표.get(등급, 표["free"])`이면 에러 없이 `free` 값이 나온다.
- 같은 이유로 운영 상수(`_GLOBAL_AI_DAILY` 3000 → 새 상한 250)도 운영 파일을 안 고치면 옛 값이 그대로 산다.

## 지침

1. **새 키·새 상수를 rules.py에 만들면 같은 작업 안에서 운영 값 파일(`rules_values.py`)에도 넣는다.** 승격 전 체크리스트 한 줄: `grep -n "새이름" server/constraints/*.py`.
2. 운영 값 파일 적용 함수는 **rules.py에 없는 이름을 거부**(AttributeError)하게 해 두면 오타·삭제는 잡히지만 "빠진 키"는 못 잡는다 → 짝 테스트(기본값 단언)를 **운영 값을 얹은 상태에서도** 돌리는 게이트를 둔다(승격 게이트가 서비스 폴더에서 돌린 것이 이 사례).
3. 조회가 기본값으로 폴백하는 구조라면, 새 등급 전용 테스트는 "운영 값을 얹은 상태에서 그 등급의 값이 기본 등급과 달라야 함"까지 단언한다.
4. 개발 폴더의 기본값 테스트가 운영 값(서비스 폴더만 있음)을 못 본다는 사실 자체가 맹점이다 — 서비스 폴더에서 한 번 더 도는 단계를 생략하지 않는다.
