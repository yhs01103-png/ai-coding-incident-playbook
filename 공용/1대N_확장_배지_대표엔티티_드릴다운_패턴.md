# "알림 배지 1개 = 엔티티 1개"였던 설계가 엔티티 여러 개로 늘어날 때 (범용)

알림/배지/뱃지형 UI가 "지금 이 앱에서 이 종류의 엔티티는 항상 최대 1개"라는
암묵 전제 위에 만들어져 있다가(예: "대기 중인 도전장 1건"), 나중에 그
엔티티가 여러 개 동시에 존재할 수 있게(예: "회사를 여러 개 소유 가능") 도메인
자체가 확장될 때 반복되는 설계 문제.

## 문제

배지 하나 → 탭 하나 → 상세 화면 하나로 바로 연결되는 구조는 엔티티가 항상
1개일 때만 자명하다. 엔티티가 N개로 늘면 "배지를 눌렀을 때 어느 엔티티의
상세 화면으로 보낼지"가 더 이상 자명하지 않다 — 이 시점에 흔히 나오는
과잉설계는 "알림 센터"류의 새 목록형 화면을 통째로 새로 만드는 것인데,
엔티티가 실제로 동시에 여러 개 걸리는 경우가 드물다면 이건 문제 크기 대비
과한 투자다.

## 해법 — 새 화면 대신 "대표 엔티티 고정 + 그 안에서 드릴다운"

1. 배지는 여전히 **하나만** 유지하고, 목적지를 "대표 엔티티"(보통 그
   도메인에서 이미 존재하는 정렬 기준의 1등 — 예: 가장 규모가 큰 것, 가장
   최근 것)의 상세 화면으로 고정한다. 새 알림 목록 화면을 만들지 않는다.
2. 그 상세 화면 안에 "이 엔티티와 같은 종류의 나머지 것들"을 나열하는 보조
   섹션(예: "계열사", "관련 항목")을 추가해서, 실제로 알림이 걸린 엔티티가
   대표 엔티티가 아니었더라도 한 번 더 탭해서 도달할 수 있게 한다.
3. 이 보조 섹션은 엔티티가 1개뿐이면(가장 흔한 경우) 자동으로 숨겨서, 평소엔
   기존 화면과 다를 게 없다 — 화면이 늘어나는 게 아니라 기존 화면에 조건부
   섹션 하나가 추가되는 것뿐이다.

이 접근의 핵심은 "새 UX 화면/네비게이션 계층을 만들지 않고, 이미 있는
상세→목록 탐색 구조를 한 단계 더 씀"이다 — 알림 센터형 UI는 엔티티가 실제로
자주 여러 개 동시에 걸리는 도메인(이메일 받은편지함 등)에서나 투자 가치가
있다.

## 실측 사례 (poker_app, ADR-119/120, 2026-09-13~14)

"라이벌→플레이어 회사 도전" 배지는 원래 "대기 중 도전 1건"이라는 전제로
설계됐다(회사가 1개뿐이던 시절). 이후 다중 소유(ADR-109)로 플레이어가 회사를
여러 개 가질 수 있게 되면서, "매물 제안/역제안" 배지를 새로 추가할 때 같은
문제가 재현됐다 — 회사 여러 개가 각자 대기 중 제안을 가질 수 있어 "배지 하나
→ 어느 회사로 보낼지"가 불명확. 사용자가 직접 제안한 해법(레퍼런스 앱의
실제 구조를 조사해 검증)이 정확히 위 2단계 패턴이었다: 배지는 항상
"peak_season_earnings 기준 가장 큰 보유 회사"로 고정 이동, 그 회사 상세
화면에 "계열사" 섹션(나머지 보유 회사 목록 + 대기 제안 있는 회사는 뱃지
표시)을 신설. 새 알림 센터 화면은 만들지 않았고, 회사가 1개뿐인 대다수
플레이어에게는 계열사 섹션 자체가 안 보인다(조건부 렌더링).
