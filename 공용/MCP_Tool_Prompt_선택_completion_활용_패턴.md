# MCP 서버에서 Tool과 Prompt를 헷갈리는 함정 — "타이핑하면 후보가 뜨는" 기능은 Tool로 못 만든다

## 문제

사용자가 슬래시커맨드처럼(`/이름`) 타이핑해서 사전 등록된 항목 중 하나를
직접 골라 쓰는 UX를 MCP 서버에 만들고 싶을 때, `@server.tool()`만 추가하면
이 UX 자체가 절대 안 나온다 — Tool은 "에이전트가 스스로 판단해서 호출
여부를 정하는" 프리미티브라, 애초에 사용자가 이름으로 직접 골라 부르는
대상이 아니다.

## 원인

MCP 스펙은 Tool과 Prompt를 서로 다른 프리미티브로 나눈다:

- **Tool** — 에이전트가 스스로 판단해서 호출. 사용자에게 "메뉴"로 안 보임.
- **Prompt** — 클라이언트(Claude Code 등)가 `/서버명:이름` 같은
  슬래시커맨드로 사용자에게 직접 노출하는 대상. **인자 자동완성**
  (`completion/complete` 프로토콜 메서드)도 Prompt(또는 리소스템플릿)
  전용이다 — Tool엔 이 메커니즘 자체가 없다.

"타이핑하면 그 텍스트에 맞는 후보가 뜬다"는 요구사항은 정확히 이
`completion/complete` 메커니즘이 하는 일이라, Tool로는 처음부터 구현이
불가능하고 Prompt로 가야만 한다.

## 해법

- **실행 대상 기준으로 먼저 구분**: 에이전트(Claude Code 등)가 실제로 뭔가를
  하게 만들고 싶다 → Tool. 사용자가 직접 골라서 트리거하는 메뉴/스니펫/
  바로가기 → Prompt.
- **문서보다 설치된 SDK 소스를 먼저 확인**: 라이브러리 문서만 보고 지원
  여부를 가정하지 말고, `inspect.getsource()`로 실제 설치된 패키지의
  데코레이터/핸들러를 직접 읽고 결정한다(실측: `mcp==2.0.0`의
  `MCPServer.completion()` 데코레이터 소스를 직접 확인한 뒤에야 Tool 대신
  Prompt로 확정했다 — SDK 버전에 따라 지원 프리미티브가 다를 수 있다).
- **기존 게이팅 데코레이터 재사용 가능 여부도 소스로 확인**: `@server.tool()`
  위에 씌운 자체 게이팅 데코레이터(예: "이 기능이 꺼져 있으면 에러값
  반환")가 있다면, `server.prompt()`도 원본 함수를 그대로 반환하는지
  (데코레이터가 "본체 함수는 안 바꾸고 등록만 한다"는 계약을 지키는지)
  소스로 확인한 뒤 같은 데코레이터를 재사용할 수 있다 — 반환 타입(예:
  str vs dict/list)만 새 분기로 추가하면 됨, 게이팅 로직 자체를 중복
  구현할 필요 없음.

## 중요한 단서(2026-09-08) — Claude Code CLI는 아직 completion/complete를 안 부른다

위 해법대로 서버에 `completion()` 핸들러를 스펙대로 구현해도, **Claude
Code CLI(터미널)는 슬래시커맨드 인자를 타이핑하는 동안 이 요청 자체를
보내지 않는다** — 인자 없이 `/서버명:프롬프트이름`만 치면 그냥 "필수
인자 없음"으로 즉시 실패하고, 인터랙티브하게 값을 물어보거나 후보를
띄우는 동작이 없다. GitHub 이슈 #30733("Claude Code CLI MCP Prompts do
not elicit user input for prompt arguments")로 이미 보고됐고 "not
planned"로 종료됨 — 서버 구현 문제가 아니라 **클라이언트 쪽 기능
자체가 없는 것**이라 서버를 아무리 스펙대로 고쳐도 못 고친다. `/mcp`의
"Reconnect"도 이미 뜬 로컬 stdio 서버 프로세스에 재연결만 할 뿐 코드
변경을 반영 못 한다는 점도 같이 확인(로컬 서버 코드를 고쳤으면 Claude
Code 세션 자체를 재시작해야 새 코드가 반영됨).

## 부가 — 인자 없이도 호출되게: 파라미터 기본값으로 "필수 아님"을 스키마에 반영

바로 위 클라이언트 한계의 실전 우회책. MCP SDK(`mcp/server/mcpserver/
prompts/*.py`, `Prompt.from_function`)는 등록된 함수의 **파이썬 파라미터
기본값 유무**로 그 인자의 스키마 `required`를 결정한다(`func_metadata`가
만든 pydantic 모델의 `model_json_schema()`가 `required` 배열을 채우는
방식 그대로 가져다 씀) — 그래서:

```python
# 이전: name이 없으면 클라이언트가 호출 자체를 못 함
def snippet(name: str) -> str: ...

# 이후: 기본값만 추가하면 스키마상 required=False가 되고,
# 클라이언트가 인자 없이 불러도 통과해서 name="기본값"으로 실행됨
def snippet(name: str = "기본값") -> str: ...
```

문서보다 소스를 직접 읽어야 확인되는 부분(`Prompt.render()`가 `missing
= required - provided`로 검사하는데, 애초에 required 집합에 안 들어간
인자는 없어도 통과) — 기본값에 뭘 넣을지는 "인자 없이 부르면 보통 뭘
기대하나"로 정하면 된다(예: 등록된 항목 전체 안내/메타 동작을 반환하는
이름을 기본값으로).

## 부가 — 무인 트리거의 비용을 2단계로 분리하기

같은 세션에서 나온 인접 패턴. 스케줄러가 주기적으로 뭔가를 트리거할 때,
매 주기마다 무거운 리소스(LLM 세션, 무거운 프로세스 등)를 곧장 스핀업하면
사람이 응답을 안 해도 비용이 이미 나간다 — 대신 (1) 저비용 알림(OS 토스트
등)만 먼저 띄우고, (2) 사람이 그 알림에 실제로 응답한 주기에만 무거운
리소스를 연다. "항상 도는 무거운 폴링" 대신 "저비용 게이트 뒤에 무거운
실행을 숨기는" 구조.

Windows 토스트로 이 게이트를 구현할 때 실측으로 확인된 것 — `win11toast.
toast()`는 **블로킹 호출이고 자체 타임아웃이 없다**(activated/dismissed/
failed 중 하나가 끝날 때까지 `asyncio.wait()`로 무한정 대기). "N분 안에
응답 없으면 포기"를 만들려면 별도 스레드에서 `toast()`를 돌리고 메인
스레드가 `thread.join(timeout=N)`으로 기다린 뒤 결과 dict를 확인하는
식으로 감싸야 한다 — 라이브러리 자체엔 이런 타임아웃 옵션이 없다.

## 일반화

- MCP 서버를 짤 때 "사용자가 직접 부르는 기능"과 "에이전트가 판단해서
  쓰는 기능"을 먼저 구분하고 시작하면, Tool/Prompt 중 뭘 써야 하는지가
  자동으로 정해진다 — 나중에 UX가 기대와 다르게 나온 뒤에야 프리미티브를
  잘못 골랐다는 걸 깨닫는 것보다 훨씬 싸다.
- SDK 버전마다 지원 프리미티브/메서드가 다를 수 있다 — 문서보다 설치된
  패키지 소스를 먼저 확인하는 습관이 안전하다.
- 무인 트리거(스케줄러, 워치독 등)를 만들 때는 "매 주기 비용"과 "응답
  없을 때 비용"을 분리해서 설계하는 게 기본이어야 한다 — 저비용 게이트를
  앞에 두는 순서.
- MCP 스펙에 있는 기능(completion 등)이 서버에 정확히 구현돼 있어도,
  **클라이언트가 그 스펙 부분을 실제로 부르는지는 별개 문제**다 — 서버
  구현을 아무리 고쳐도 클라이언트 갭은 못 메운다. 파라미터 기본값처럼
  클라이언트 갭을 우회하는 별도 방어선을 스키마 레벨에서 찾아두면 좋다.

2종 + `completion()` 핸들러 신설. 같은 라운드에서 코어 세션 스케줄러

게이트를 위해 위 `win11toast` 블로킹/타임아웃 문제를 직접 겪고 해결했다.

SSOT_Explorer(D-111, 2026-09-08) — 실사용 중 사용자가 `/mcp__ssot-
explorer__snippet`을 인자 없이 호출했다가 "Missing required argument"로
막히는 걸 직접 겪음 → 클라이언트가 completion/complete를 아예 안 부른다는
걸 위에서 확인 → `snippet(name: str = "0")`처럼 기본값을 줘서 무인자
호출이 통과하게 우회. 등록된 이름 목록을 "0"번(관례상 메타/목록-확인
슬롯)에 정해두고 그걸 기본값으로 삼아, 인자 없이 부르면 자연스럽게
"뭐가 등록됐는지 보여주는" 동작으로 떨어지게 설계 — 기본값을 아무거나
고르지 않고 "무인자 호출이 원래 기대하는 의미"에 맞춘 사례.
