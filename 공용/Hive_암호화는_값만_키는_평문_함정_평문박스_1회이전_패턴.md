# Hive 암호화는 값만 — 키는 평문으로 남는다, 그리고 평문 박스를 암호화 박스로 옮기는 법 (범용)

대화·알림·메시지처럼 개인정보가 든 Hive 박스를 `HiveAesCipher`로 암호화할 때 쓰는 체크리스트.
Market_Agent_App(2026-10-07 P1 → 실기기 검증)에서 실측했고, 같은 구조(평문 `Hive.openBox`로 대화 기록을
저장)인 Lazzy_App_OS_Monorepo 클라이언트(chat_history·context_history·settings 박스)에도 해당한다.

## 함정 1. 암호화되는 건 값뿐이다 — 박스 키(key)는 파일에 평문으로 남는다

`Hive.openBox(name, encryptionCipher: cipher)`는 **값(value)** 프레임만 AES로 암호화한다. `box.put(key, value)`의
`key`는 암호화되지 않는다. 그래서 키를 `"$패키지|$알림키|$제목|$본문"`처럼 **내용으로 만들면** 값을 암호화해도
그 내용이 파일에 그대로 읽힌다. 중복 판정용 "이미 본 항목" 박스(`Box<String>`)가 특히 위험하다 — 값은 의미 없는
표식이고 정보는 전부 키에 들어 있다.

실측(Market_Agent_App, 2026-10-07): 암호화 적용 후에도 `seen_listings.hive`에서 10자 이상 이어지는 한글 구간이
255건(최장 114자) 남았다. 다른 암호화 박스(키가 id인 것)는 우연 일치 수준뿐이었다(→ 판정법은
`Flutter_실기기_adb_탭_스크린샷_자동검증_절차.md` "앱 저장 데이터 평문 점검"). 키가 알림 제목·본문을 담는다는
것은 설계 문서(중복 판정 키 구성)에서의 추정이고, 값은 열람하지 않았다.

**대응**: 사용자 내용이 들어가는 박스 키는 해시(SHA-256 등 `crypto` 패키지)로 바꿔 저장한다. 중복 판정은 키 일치만
쓰므로 해시로 충분하다. 기존 평문 키는 아래 "1회 이전" 때 해시로 변환해 옮긴다.

## 함정 2. 이전 버전이 만든 평문 박스를 그냥 암호화 모드로 열면 깨진다

이미 설치된 앱에 암호화를 추가하면, 디스크의 박스 파일은 평문이다. 같은 이름을 `encryptionCipher`로 열면
읽기 오류가 나거나 빈 박스처럼 보인다. 그렇다고 오류를 잡아 "평문으로 되돌려 열기"를 하면 이미 암호화된 박스를
깨뜨린다. → **박스마다 "암호화 완료" 표식**을 보안 저장소(Android Keystore 기반)에 두고 분기한다.

```dart
// 키: 보안 저장소에 한 번 생성. 읽기 자체가 실패하면 예외를 그대로 낸다(평문으로 폴백 금지).
// 박스 열기:
if (await secrets.read('hive_box_encrypted.$name') == '1') {
  return Hive.openBox<T>(name, encryptionCipher: cipher);        // 이미 이전됨
}
final plain = await Hive.openBox<T>(name);                       // 평문 박스 읽기
final data = Map.of(plain.toMap());  await plain.close();
await Hive.deleteBoxFromDisk(name);                              // 평문 파일 제거
final box = await Hive.openBox<T>(name, encryptionCipher: cipher);
await box.putAll(data);                                          // 필요하면 여기서 키를 해시로 변환
await secrets.write('hive_box_encrypted.$name', '1');            // 표식은 맨 마지막
```

- 표식은 **맨 마지막**에 쓴다. 중간에 죽으면 다음 실행이 평문 경로를 다시 탄다(평문 파일을 지우기 전에
  죽었다면 데이터가 남아 있고, 지운 뒤 죽었다면 이미 `putAll` 전이라 손실 — 아래 주의 참고).
- 단위 테스트에서는 `init()`을 부르지 않으면 평문으로 열리게 해 두면 기존 테스트가 그대로 돈다. 이전 로직은
  가짜 `secrets` 구현을 주입해 따로 테스트한다(106줄 테스트로 이전·재실행·표식 케이스 고정).

## 주의 — 복구 정책이 데이터 손실이다

"키를 잃었거나 파일이 깨졌을 때 박스를 비우고 새로 시작"은 앱이 죽는 것보다 낫지만 **그 박스의 기록이 전부
사라진다.** 알림 원문·판단 캐시처럼 다시 만들 수 있는 박스에는 괜찮고, **사용자 대화 기록·설정은 그대로
적용하면 안 된다** — 백업 후 비우기, 또는 사용자에게 알림 후 비우기로 바꾼다. 또한 안드로이드 백업이 켜져 있으면
(`allowBackup` 기본값) 재설치·기기 변경 후 박스 파일만 복원되고 Keystore 키는 복원되지 않아 이 복구 경로가 실제로
발동할 수 있다 `[추정 — 이번에 복원 시나리오는 재현 안 함]` → `Android_납품전_debug서명_allowBackup_점검_패턴.md`와 같이 본다.
